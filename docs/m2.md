# M2 — AI 파트 결과

> 목표: 음성인식 구조 설계, 음성입력 처리 PoC 및 여행상품 선택 기능과의 연동 검증

## 1. 음성인식 구조 설계 ✅

- 4단계 파이프라인: VAD(Silero) → STT(Groq Whisper) → 명령 해석(Groq GPT-OSS 120B) → 검증
- 클래스 구조는 StarUML **Voice AI Server 클래스도**와 1:1로 구현 (VoiceController, VadDetector, SttClient, CommandParser, CommandValidator + DTO 3개)
- FE ↔ AI 서버 계약: 요청 `audio + ScreenContext`, 응답 `VoiceResponse { recognizedText, commands, pending }`
- 상세: [pipeline.md](pipeline.md)

## 2. 음성입력 처리 PoC ✅

| 항목 | 내용 |
|---|---|
| 서버 | FastAPI, `POST /api/v1/voice/command` |
| 입력 | 브라우저 녹음 → 16kHz 모노 WAV (데모 페이지에서 변환) |
| VAD | 말한 구간만 잘라 STT로 보냄. 무음이면 STT 호출 안 함 |
| STT | whisper-large-v3-turbo, 한국어 + 여행 용어 프롬프트 |
| 명령 해석 | JSON 모드, temperature 0, 화면 정보를 같이 보냄 |
| 안전장치 | 결제는 음성 불가, 신청 화면 이동은 "네" 확인 후, 화면에 없는 값은 차단 |

## 3. 여행상품 선택 기능 연동 검증 ✅

**(1) 자동 테스트 — `pytest`, 16개 통과**

Groq 대신 가짜 응답을 넣어 서버 쪽 처리 흐름을 검증했다.

| 구분 | 확인한 것 |
|---|---|
| 선택 | "두 번째 거" → 화면 2번째 상품의 tourId / 화면에 없는 tourId는 차단 / 빈 목록에서 선택 차단 / LLM에 화면 순서대로 목록 전달 / 검색+선택 한 문장 |
| 검색 | "10월" → 날짜 범위 변환(지난 달은 내년) / 잘못된 테마 제거 |
| 구성·확인 | 고를 수 없는 등급·없는 옵션 제거 / checkout은 확인 대기 / "응" → 대기 명령 실행 |
| 실패 | 무음 / 깨진 JSON / 허용 안 된 action → unknown |
| API | 정상 응답, 잘못된 context → 400 / WAV 형식 검사 |

**(2) 데모 페이지 — `/demo/`**

여행상품 목록(4개)을 띄워놓고 말하거나 문장을 입력하면, 서버 명령대로 카드가 선택되고 상세가 열린다.
브라우저 자동화로 확인한 흐름: "두 번째 거 보여줘" → 제주 효도 힐링(tourId 23) 선택·상세 표시 / "골프 여행 찾아줘" → 1개로 필터 / "이걸로 예약할게" → 확인 창 → "네" → 신청 화면 이동.

**(3) 실제 Groq 검증 — `python scripts/verify_select.py`**

선택·검색·구성·확인·실패 발화 13개를 실제 모델로 돌려 통과 여부와 응답 시간을 `verification_result.md`로 남긴다.
→ API 키가 있는 PC에서 실행한 결과를 이 문서에 붙인다.
